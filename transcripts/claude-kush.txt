Evolutionary search CAN be adjacent to RL — in specific framings
OpenAI's 2017 paper ("Evolution Strategies as a Scalable Alternative to Reinforcement Learning") made this precise. If you perturb your policy parameters with Gaussian noise, evaluate complete rollouts, and update parameters proportional to how each perturbation scored, you're computing a finite-difference estimate of the gradient of expected return:
θ ← θ + α · (1/nσ) · Σ F(θ + σεᵢ) · εᵢ
That's structurally similar to a REINFORCE policy gradient — you're still optimizing expected return, just with a black-box gradient estimator instead of backprop through time. In that framing, ES is doing policy optimization, which is an RL objective.
There are also genuine hybrid ERL algorithms (Khadka & Tumer 2018, CERL, etc.) that maintain an evolutionary population and run RL gradient updates — injecting RL-trained actors back into the gene pool and using replay experience to improve the population. These are legitimately both things at once.

But what Kushagra built doesn't appear to be either of those
What's described is:

A genetic algorithm with mutation, crossover, and elite selection
Controllers scored on complete rollouts → fitness value
No gradient estimation, no policy gradient update, no RL-trained actor injection

The deeper reason it isn't RL isn't just the lack of gradients — it's the absence of temporal credit assignment. RL (even policy gradient RL) tries to answer: which action at which timestep contributed to the outcome? That's the core hard problem RL is designed to solve. Evolutionary search skips that question entirely. It scores the whole rollout, keeps the winners, discards the losers, and breeds the next generation. It never asks why a particular braking decision at turn 1 caused a crash at the Lesmo 800 meters later.
That's actually why it worked where PPO didn't — it sidesteps the credit-assignment problem rather than solving it. PPO stalls because early aggressive acceleration earns local progress reward but sets up late-race crashes, and the gradient signal can't propagate that causality reliably over a full lap. Evolutionary search doesn't care — it just knows the rollout finished or it didn't.

What evolutionary RL actually is
The canonical version is ERL (Khadka & Tumer, 2018 — "Evolution-Guided Policy Gradient in Reinforcement Learning"). The core idea is running an evolutionary population and a gradient-based RL agent in parallel, with a shared replay buffer connecting them:
Population of actors (evolved via genetic algorithms)
+
One RL agent (DDPG or TD3)
+
Shared replay buffer

Each generation:
1. Evaluate all population actors → fitness scores
2. Run RL agent for N steps → transitions go into shared replay buffer
3. All actors, including population members, can use that buffer for gradient updates
4. Evolve the population (selection, mutation, crossover)
5. If the RL agent's policy is competitive, inject it into the population
The key insight is that each side fixes the other's weakness. Evolution explores broadly and discovers rare behaviors (like completing a lap) that gradient descent misses. RL then exploits the transitions from those discoveries to do efficient credit assignment and improve everyone. The shared replay buffer is the bridge — once any actor in the population does something useful, those transitions are available to the RL agent to learn from.
There are variants: CEM-RL uses Cross-Entropy Method instead of a full genetic algorithm. PDERL adds policy distillation. QD-RL combines quality-diversity search (MAP-Elites) with RL to maintain a behaviorally diverse archive while still doing gradient updates.

Why this maps onto exactly what happened in this project
The failure was precise: PPO stalled at ~970m because aggressive early acceleration earned local progress reward but set up crashes later, and the gradient signal couldn't propagate causality across a 90-second lap. So PPO never produced a valid lap, which meant its replay experience was always from failed rollouts, which made the gradient signal even worse. A self-reinforcing dead end.
Evolutionary search broke out of it — but by ignoring the transition-level information entirely. 27,650 candidate evaluations to produce 926 valid laps is genuinely expensive. All those transitions from failed candidates were thrown away.
ERL addresses both problems directly:

The evolutionary population discovers valid laps (which it already did here)
Those valid-lap transitions fill the replay buffer
The RL agent now has good experience to learn from — something it never had running alone
The RL agent's gradient updates then improve the population actors too
The system compounds instead of stalling


The catch: PPO is the wrong RL component for ERL
This is the important practical detail. ERL and CEM-RL use off-policy methods — DDPG, TD3, SAC — because off-policy RL can reuse experience from any actor in the population. PPO is on-policy. It can only learn from transitions generated by its own current policy. So PPO can't participate in the replay buffer sharing that makes ERL work.
To actually implement this, the RL component would need to switch to TD3 or SAC. Both are designed for continuous control (continuous steering, throttle, brake — exactly this problem), tend to outperform PPO on continuous action spaces in general, and can legitimately share a replay buffer with the evolved population.

The additions needed:

Add a shared replay buffer that both the RL agent and population actors write to

The realistic outcome: the evolutionary component keeps finding diverse valid laps and exploring new lines, while TD3 does gradient updates on the resulting transition data to push toward the 79.662s reference target — which is a different problem than just completing a valid lap. Evolutionary search found 89.983s but closed the gap to F1 pace slowly; RL's gradient efficiency is where the remaining 10 seconds likely lives.
